## ARC 2.0.0 to installed 2.0.2

Both primary methods describe ARC-based paired assays. GSE296875 GEO explicitly identifies CellRanger-ARC v2.0.0. GSE223843 GEO calls its processing Cell Ranger v2.0.0; its primary methods identify Cell Ranger ARC 2.0.0 and downstream scATAC-pro 1.4.2. The distinction between the GEO shorthand and the primary assay recipe is retained. Both sources declare GRCh38/hg38. The development primary specifies GRCh38-2020-A and filtered GENCODE v32; the inspected external main methods do not specify the exact reference package/GTF. [Development methods](https://pmc.ncbi.nlm.nih.gov/articles/PMC12805840/), [external methods](https://pmc.ncbi.nlm.nih.gov/articles/PMC11103255/).

The [official ARC release notes](https://www.10xgenomics.com/support/software/cell-ranger-arc/latest/release-notes/release-notes), sections 2.0.1 and 2.0.2, document:

- 2.0.1: sample-index handling in FASTQ headers, an all-zero per-barcode GEX metric, aggregation/reporting integer/metric fixes and restored mkref threads.
- 2.0.2, 2022-08-18: NovaSeq i5-orientation autodetection during mkfastq after a reagent-recipe change.
- The separate 2025-02-20 entry under 2.0.2 announces 2024-A references; it does not announce new fragment arithmetic.

No patch change to genomic alignment, Tn5 interval adjustment, duplicate definition or molecular count units is documented there. The start/end/**barcode** duplicate rule, Hamming-distance-one barcode correction and fragment reference/version headers were already introduced in 2.0. **[Inference]** 2.0.2 is a reasonable candidate for already-demultiplexed 2.0.0 multiome inputs once header/index handling is qualified. This is not a guarantee of identical results. Index handling can matter for particular submitted headers or pooled inputs. Later 2.1/2.2 versions include other changes and are not proposed here.

The official 2.0 fragment definition is particularly useful: one row is a unique ATAC fragment after collapsing duplicate read pairs. Its BED interval uses +4 at the left and −5 at the right; coordinates are 0-based with an exclusive end. Column five records supporting read pairs, including duplicates. Thus the frozen common-body-overlap endpoint must count each qualified interval once per nucleus/window, not weight by column five and not count two insertion events per fragment. [ARC 2.0 fragment specification](https://www.10xgenomics.com/support/software/cell-ranger-arc/2.0/analysis/outputs/fragments-file).

GSE296875 GEO independently declares its deposited fragment files to be ARC outputs with start/stop adjusted to Tn5 cuts. It also explicitly says its raw HDF5 includes ARC-called ATAC peaks that the authors did not use. These are methods/schema facts. They support direct fragment counting on the fixed 306,706 windows; they do not justify using the external author's called-peak matrix as a complete fixed-window measurement. No author matrix values were inspected.

## Feasible route and explicit remaining limits

The [official ARC 2.0 pipeline](https://www.10xgenomics.com/support/software/cell-ranger-arc/2.0/analysis/running-pipelines/single-library-analysis) requires both GEX and ATAC; it cannot run either alone. Technical lanes from the same library can be listed together; the count instance is per GEM well. Therefore the existing software route is paired-library ARC 2.0.2 processing, after read-role/synchronization, canonical barcode translation, reference and roster qualification, followed by the already fixed fragment-body counter and raw complete-axis RNA pseudobulk. A manual ATAC-only alignment/shift pipeline is not established as equivalent merely because an aligner is installed.

The separate GEX feasibility report already inventories twelve GEX and twelve ATAC technical runs for six people. The RNA annotation receipt resolves its former gene-schema/ordered-axis gap. Raw barcode correction/orientation and paired whitelist translation still require qualification; the 100-spot pilot did not choose or apply an orientation. The lineage branch still requires an admitted RNA-only seven-lineage crosswalk. The separately declared donor-global branch avoids that crosswalk, but still needs a fixed matched-nucleus roster and joint-pass/source-filter qualification. Neither branch gains independent validation by changing its target after external observability is known.

For a subsequently authorized individual processing job, a reasonable initial reservation is **cpu/nslab, 8 CPUs, 64GB, 90h**, ARC `--localcores=8 --localmem=64`, one fresh output directory and job-specific logs. This is an allocation proposal, not a measured runtime or submission. Current vendor guidance gives an 8-core/64GB/1TB-free-disk minimum; its published 14h08m example is a different PBMC dataset and ARC 2.1, not an ETA for these libraries. [Current ARC system requirements](https://www.10xgenomics.com/support/software/cell-ranger-arc/downloads/system-requirements). Existing metadata totals 175,932,536,369 bytes of normalized GEX+ATAC SRA or 333,256,868,732 bytes of original compressed four-class FASTQs, before export/alignment intermediates. Scratch capacity, retention and an actual per-person byte cap must be established before processing. No full-run acquisition or new job is authorized by this report.
